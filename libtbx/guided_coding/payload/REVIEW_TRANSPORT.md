# Outside Reviewer transport, when a gate is due

This file is read only for a full-path integration, publication batch, or release kit. The Developer decides exactly what crosses to the Outside Reviewer. The reader gets the **whole archive**, not a summary or a hash pasted in its place.

1. Prepare packet files including `README_FIRST.md`, `PROOF_SUMMARY.md`, and the proposed `APPROVAL_REPORT.md` with the **complete tested diff and exact new test code**. Put the provisional verdict at the end of the proof summary so the reader can examine evidence first. Include code identity, test output and exit statuses, provenance of the decisive criterion, findings and dispositions. For a batch that will be published, also include `OUTGOING.txt` (key lines only: the exact outgoing commits, bases, trees, remotes and refspecs), `SERVER_SUITE.txt`, `ROSTER_COMPARISON.txt` and `PUBLICATION_NOTES.md`, in the formats listed in `PUBLICATION_PACKET.md`, and run `screen_check.py check-draft publication PACKET_DIR` before freezing, so that one reading can address integration and publication together. Freeze once with the central tool, `libtbx.python -I -B "$GC_PAYLOAD_ROOT/tools/screen_check.py" freeze PACKET_DIR` (set `GC_PAYLOAD_ROOT` in this shell call). For a code change, run the screen check before presenting a result.
2. After freezing, place `APPROVALS.md` and `CHECKER.md` in a **separate** companions directory **outside the frozen packet**, and `ERRATA.md` there for clerical corrections as WORKER.md defines them (one definition there, including a misplaced verified file supplied with `--corrections` and a checker-refused slip that needs a refreeze and a short addendum reading; this replaces the earlier reading of any correction as a new packet). A correction of substance still needs a new packet. An `ERRATA.md` added after the reading leaves the packet identity, and so the reading's binding, unchanged; name such errata in the decision screen's LIMITS and the ticket copy, and offer them to the reviewer with the next reading. The helper refuses a nested companions directory or copies of these reserved companion filenames in the packet before writing. The checker sheet and later approval are not added to or silently applied to the frozen packet.
3. Run the central tool `libtbx.python -I -B "$GC_PAYLOAD_ROOT/tools/review_bundle.py" PACKET_DIR COMPANIONS_DIR REVIEW_BUNDLE.tgz` (set `GC_PAYLOAD_ROOT` in this shell call). Place `REVIEW_BUNDLE.tgz` **in the frozen packet's own parent directory**, not in a separate output folder; an alias to that parent is allowed. The tool refuses a missing or changed packet and prints the archive SHA-256 and packet identity. The bundle contains the packet archive, companions, and a checksum list without a self-hash. Make one `REVIEW_MESSAGE.md` in Downloads: a factual cover with **explicit labeled lines** for the change, bundle hash, **SHA-256 of the packet's top-level `MANIFEST.sha256`** as packet identity, base, host, process count used in checks, errata status, limits, the two review questions and the scope asked for (integration, publication, or both), followed by the **full central `OUTSIDE_REVIEWER_BRIEF.md`** text. Say `none` or `not applicable` on a required line only if that is the fact; do not omit it. Give no conclusion in the cover. Reopen the actual message file to confirm the complete brief, both identities and every labeled field are present. Give the Developer that message and the bundle together. If an available tool can deliver the Developer-selected exact files to an independent reader, ask him which artifact to send and use it; otherwise give him one simple manual transfer. Do not contact anyone without his authorization.
4. File the verbatim reply **outside** the frozen packet. Check the archive and packet identities and the `Scope:` line in that reply and disposition every finding. Identical repeated `Packet identity:`, `Verdict:` or `Scope:` lines (for example the closing block repeated in a summary) count as one; conflicting repeats are refused, including indented, bulleted, quoted or bold ones (this replaces refusing every repeat, and reading only column-0 lines). Never edit the reply. A reading scoped to both gates serves the RESULT and the PUBLICATION screen of that packet. A re-staged or otherwise changed packet has a new identity and needs its own reading or a reassessment addendum bound to it, possibly short; a reading is never reused across identities. Earlier test evidence carries over to a restage only under WORKER.md's restage carry-over rule. Only then prepare the final result or publication decision. The Outside Reviewer never authorizes integration or a push; that word belongs to the Developer.

The bundle helper establishes transport integrity and file presence. It cannot authenticate who wrote a companion, whether tests really ran, or whether a condition was genuinely met. A release-kit bundle can follow the same transport layout using its own packet and companions, but the kit itself must be reviewed before Worker use.
