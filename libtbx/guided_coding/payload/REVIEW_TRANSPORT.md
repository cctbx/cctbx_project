# Outside Reviewer transport, when a gate is due

This file is read only for a full-path integration, publication batch, or release kit. The Developer decides exactly what crosses to the Outside Reviewer. The reader gets the **whole archive**, not a summary or a hash pasted in its place.

1. Prepare packet files including `README_FIRST.md`, `PROOF_SUMMARY.md`, and the proposed `APPROVAL_REPORT.md` with the **complete tested diff and exact new test code**. Put the provisional verdict at the end of the proof summary so the reader can examine evidence first. Include code identity, test output and exit statuses, provenance of the decisive criterion, findings and dispositions. Freeze once with the central tool, `python3 -I -B "$GC_PAYLOAD_ROOT/tools/screen_check.py" freeze PACKET_DIR` (set `GC_PAYLOAD_ROOT` in this shell call). For a code change, run the screen check before presenting a result.
2. After freezing, place `APPROVALS.md` and `CHECKER.md` in a **separate** companions directory **outside the frozen packet**, and `ERRATA.md` there if a correction is needed. The helper refuses a nested companions directory or copies of these reserved companion filenames in the packet before writing. The checker sheet and later approval are not added to or silently applied to the frozen packet.
3. Run the central tool `python3 -I -B "$GC_PAYLOAD_ROOT/tools/review_bundle.py" PACKET_DIR COMPANIONS_DIR REVIEW_BUNDLE.tgz` (set `GC_PAYLOAD_ROOT` in this shell call). Place `REVIEW_BUNDLE.tgz` **in the frozen packet's own parent directory**, not in a separate output folder; an alias to that parent is allowed. The tool refuses a missing or changed packet and prints the archive SHA-256 and packet identity. The bundle contains the packet archive, companions, and a checksum list without a self-hash. Make one `REVIEW_MESSAGE.md` in Downloads: a factual cover with **explicit labeled lines** for the change, bundle hash, **SHA-256 of the packet's top-level `MANIFEST.sha256`** as packet identity, base, host, process count used in checks, errata status, limits and two review questions, followed by the **full central `OUTSIDE_REVIEWER_BRIEF.md`** text. Say `none` or `not applicable` on a required line only if that is the fact; do not omit it. Give no conclusion in the cover. Reopen the actual message file to confirm the complete brief, both identities and every labeled field are present. Give the Developer that message and the bundle together. If an available tool can deliver the Developer-selected exact files to an independent reader, ask him which artifact to send and use it; otherwise give him one simple manual transfer. Do not contact anyone without his authorization.
4. File the verbatim reply **outside** the frozen packet. Check the archive and packet identities in that reply and disposition every finding. Only then prepare the final result or publication decision. The Outside Reviewer never authorizes integration or a push; that word belongs to the Developer.

The bundle helper establishes transport integrity and file presence. It cannot authenticate who wrote a companion, whether tests really ran, or whether a condition was genuinely met. A release-kit bundle can follow the same transport layout using its own packet and companions, but the kit itself must be reviewed before Worker use.
