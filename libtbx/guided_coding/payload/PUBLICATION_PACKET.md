# Publication packet checklist

Read for a batch that will be published. Every file below sits at the
**top level** of the packet directory; the checker looks nowhere else,
except that a verified file frozen in the wrong place can be supplied
from a correction companion (WORKER.md, `--corrections`). Companions
(`APPROVALS.md`, `CHECKER.md`, `ERRATA.md`) stay outside it
(REVIEW_TRANSPORT.md); the draft and the final check both refuse them
inside.

| File | Checked by the tool | Format |
| --- | --- | --- |
| `README_FIRST.md` | not checked | Reading order for the reviewer. |
| `PROOF_SUMMARY.md` | not checked | Evidence first; provisional verdict at the end. |
| `APPROVAL_REPORT.md` | RESULT | From `templates/APPROVAL_REPORT.md`, with the complete `CHANGE.diff`. |
| `CODE_IDENTITY.txt`, `RUN_LOG.txt`, `CHANGE.diff` | RESULT | As in WORKER.md. |
| `OUTGOING.txt` | PUBLICATION, draft | Key lines only, generated by `publication_precheck.py outgoing`; below. |
| `SERVER_SUITE.txt` | PUBLICATION, draft (first line, NOT RUN waiver form) | Below. |
| `ROSTER_COMPARISON.txt` | PUBLICATION, draft (non-empty) | Below. |
| `PUBLICATION_NOTES.md` | not checked | Public description, source manifest hash, companions, rollout pointer. |
| `RESTAGE_COMPARISON.txt` | not checked | After a restage only (WORKER.md). |
| `MANIFEST.sha256` | freeze, verify | Written by `screen_check.py freeze`; never by hand. |

**`OUTGOING.txt`.** Generate it before packaging by running, once per repository:
`python3 -I -B "$GC_PAYLOAD_ROOT/tools/publication_precheck.py" outgoing REPO --commit C --remote origin --branch master --fetch >> PACKET/OUTGOING.txt`
Standard output carries only the block (notes about push settings go to
standard error), so each call appends one repository's block; blocks need
no separator. If any call fails, stop, delete the partial file and start
again. Do not use `--output` here: it writes a new file and refuses an
existing one, so it cannot add a second repository's block. `--fetch` is required here and
on `check`: without it a stale remote-tracking ref can make a
multi-commit push look like one commit. It refuses a dirty working tree, a
missing remote, a remote with several push URLs, a merge commit, a
parent that is not the fetched remote tip and a chain of commits on it,
and checks what it wrote with the same parser and the `check`
comparisons. Multi-commit ranges are deferred: one commit per
repository. One block per repository; each line is `key: value` at
column 0 with one of the seven keys below; blank lines and `#` comments
are ignored; no prose and no other key (checkpoint 3: the final
PUBLICATION check applies this rule as the draft does).
Each block starts with `repository:` and has `remote`, `remote_url`,
`base`, `commit`, `tree` (40 lowercase hex each for the last three) and
`refspec: <commit>:refs/heads/<branch>` naming the block's own commit. A
key appears once per block; a repository appears once. Any key after a
`repository:` line belongs to that block, so put descriptions in
`PUBLICATION_NOTES.md`, not here.

```
repository: cctbx_project
remote: origin
remote_url: <the push URL>
base: <40 hex>
commit: <40 hex>
tree: <40 hex>
refspec: <commit>:refs/heads/master
```

**`SERVER_SUITE.txt`.** First line `SERVER_SUITE: <outcome>` (for example
`SERVER_SUITE: RUN 2026-10-12T21:00Z, 1234 passed, 3 failed`), then where
the logs are. The draft and the final check refuse any other first line
(after a byte-order mark and spaces); what the outcome says is judged by
the Developer and the reviewer. If the suite was not run, the first line starts
`SERVER_SUITE: NOT RUN`, followed somewhere by a line
`Waiver (Developer, <date>, batch <id>):` and immediately by one or more
`> ` lines quoting his words for this batch and scope.

**`ROSTER_COMPARISON.txt`.** Minimal form, one item per line:

```
baseline: <log path, date, code identity>
candidate: <log path, date, code identity>
validity: <why the baseline is valid for this comparison>
new failures: <names, or none>
fixed: <names, or none>
unchanged failures: <count or names>
```

**`PUBLICATION_NOTES.md`.** The public description (commit message or
release note text), the SHA-256 of the kit's or project's source
manifest where one applies, the companions, and the path of the rollout
plan for the named installations.

**Draft check.** Before freezing, run
`python3 -I -B "$GC_PAYLOAD_ROOT/tools/screen_check.py" check-draft publication DIR`.
It runs every publication check that needs neither the freeze, the
screen nor the reading (the three files at top level, `OUTGOING.txt`
blocks and key lines, the `SERVER_SUITE:` first line and the `NOT RUN`
waiver form, no companions inside; the final check applies the same
rules),
prints `DRAFT OK publication`, names the checks it skipped, and notes
listed files that are absent. A draft pass is not a frozen packet, a
reading or a PUBLISH decision; the Developer's PUBLISH / HOLD choice
stays his.
